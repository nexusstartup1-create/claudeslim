What I learned building cslim

I built a tool that compresses a codebase so Claude Code reads less of it. It works: 39,000 tokens down to 9,000, and a lighter mode that reaches 98%.

Then I measured what it actually cost, in dollars, across real sessions. Every configuration came out more expensive than doing nothing.

The number I was proud of turned out to be the wrong number.

Token count isn't cost. Prompt caching changes the maths: a cache read bills at about a tenth of base input, so re-reading a file is nearly free — and injecting new context is not. My tool had to prevent twelve times its own size in reading before it broke even. It didn't.

I could have shipped the 98% number and said nothing. I published the benchmarks that contradict it instead, and put a warning in the command that turns the feature on. That decision taught me more than the code did.
